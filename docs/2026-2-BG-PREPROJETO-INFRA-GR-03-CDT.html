2 Título e Cenário / Empresa Escolhida

Título: Infraestrutura em Nuvem para o Sistema de Cadastro Financeiro CDT Jacarepaguá.

Cenário: aplicação web de apoio ao cadastro de clientes do Cartão de TODOS, com formulário de identificação, endereço e seleção da modalidade de pagamento.

Repositório de referência: https://github.com/AnnaBarbara5/cdt

3 Descrição do Problema ou Necessidade do Negócio

O sistema necessita de um ambiente confiável para executar páginas PHP, processar formulários e proteger informações cadastrais. A ausência de uma infraestrutura planejada pode prejudicar a disponibilidade, a manutenção e a segurança.

Atenção a dados sensíveis: como há campos relacionados a pagamento, a solução exige tratamento rigoroso desses dados e integração segura com provedor especializado, sem armazenar números completos de cartão ou CVV.

4 Objetivo Geral da Solução

Projetar a disponibilização da aplicação web na AWS, com hospedagem de PHP, banco de dados relacional, rede segmentada, acesso seguro, monitoramento e cópias de segurança, para permitir evolução controlada do sistema.

10 Definição Preliminar de Computação, Redes, Segurança e Armazenamento

ÁreaDefinição
ComputaçãoAmbiente Linux/PHP em EC2 de pequeno porte, dimensionado após testes; gerenciamento via Elastic Beanstalk.
RedesVPC com camada web acessível via HTTPS e banco de dados em sub-rede privada; porta 3306 somente a partir da aplicação.
SegurançaHTTPS, IAM com privilégio mínimo, segredos protegidos, validação de entradas, backup e políticas de retenção.
ArmazenamentoEBS para sistema e aplicação, RDS para registros e S3 privado para cópias e arquivos autorizados.

11 Forma Prevista para Disponibilização da Solução na AWS

A publicação está prevista no AWS Elastic Beanstalk, utilizando EC2 para executar PHP e RDS MySQL para dados. Este projeto final consolida o planejamento, a implementação e a documentação da solução. Para produção plena, será necessário:

  1. Revisar o código;
  2. Retirar segredos e dados de cartão do armazenamento próprio;
  3. Integrar um provedor de pagamentos compatível;
  4. Configurar o domínio e o HTTPS;
  5. Testar os formulários;
  6. Validar a restauração de backups.

Justificativa: diferentemente de hospedagem puramente estática, essa arquitetura suporta o processamento PHP presente no projeto e permite isolar o banco de dados da internet.
