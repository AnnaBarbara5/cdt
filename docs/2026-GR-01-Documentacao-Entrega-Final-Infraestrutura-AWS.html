2 Título e Cenário / Empresa Escolhida

Título: Infraestrutura em Nuvem para o Sistema de Cadastro Financeiro CDT Jacarepaguá.

Cenário: aplicação web de apoio ao cadastro de clientes do Cartão de TODOS, com formulário de identificação, endereço e seleção da modalidade de pagamento.

Repositório de referência: github.com/AnnaBarbara5/cdt

3 Descrição do Problema ou Necessidade do Negócio

O sistema necessita de um ambiente confiável para executar páginas PHP, processar formulários e proteger informações cadastrais. A ausência de uma infraestrutura planejada pode prejudicar a disponibilidade, a manutenção e a segurança.

Atenção a dados sensíveis: como há campos relacionados a pagamento, a solução exige tratamento rigoroso desses dados e integração segura com provedor especializado, sem armazenar números completos de cartão ou CVV (implementado: tokenização mock/Stripe, últimos 4 dígitos).

4 Objetivo Geral da Solução

Disponibilizar a aplicação web na AWS, com hospedagem de PHP, banco de dados relacional, rede segmentada, acesso seguro, monitoramento e cópias de segurança, permitindo evolução controlada do sistema — com implantação demonstrada no perfil AWS Academy (EC2) e arquitetura-alvo em ECS/RDS (Terraform).

Fluxo proposto: o navegador acessa a aplicação exclusivamente por HTTPS; a aplicação consulta o RDS em rede privada. Não há acesso público direto ao banco. 10 Definição Preliminar de Computação, Redes, Segurança e Armazenamento

ÁreaDefinição
ComputaçãoAmbiente Linux/PHP em EC2 de pequeno porte (t2/t3.micro no lab); conta completa: ECS Fargate dimensionado após testes.
RedesVPC com camada web acessível via HTTPS e banco em sub-rede privada; porta 3306 somente a partir da aplicação.
SegurançaHTTPS, IAM com privilégio mínimo, segredos protegidos, CSRF, rate limit, validação de entradas, backup e políticas de retenção LGPD.
ArmazenamentoEBS para sistema e aplicação, RDS para registros e S3 privado para cópias e artefatos de deploy.

11 Forma de Disponibilização da Solução na AWS (Entrega Final)

A publicação foi implementada com EC2 + Apache/PHP + SQLite no AWS Academy (script academy-launch-ec2.ps1) e documentada para conta completa via ECS + RDS (Terraform). Antes de produção plena, recomenda-se:

  1. Revisar o código no repositório GitHub;
  2. Manter segredos fora do repositório;
  3. Usar gateway de pagamentos e HTTPS em produção;
  4. Testar formulários e critérios de aceite CA-01 a CA-10;
  5. Validar restauração de backups do RDS.

Justificativa: a arquitetura suporta o processamento PHP do projeto e isola o banco de dados da internet, conforme o diagrama preliminar.
